# FlowDesk Studio

FlowDesk Studio 是一个完全运行在浏览器中的企业级低代码流程编排、审批矩阵与运行监控演示平台。项目使用 React、TypeScript、Vite、Zustand 和 React Flow，所有数据均保存在浏览器 localStorage，不需要后端、登录或外部 API。

## 启动

需要 Node.js 20+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址（默认 `http://localhost:5173`）。建议使用 1440px 或更宽的现代桌面浏览器。

## 测试

首次运行先安装 Chromium：

```bash
npx playwright install chromium
npm test
```

Playwright 会自动启动 Vite（端口 4173），串行验证矩阵登记、三类发布阻断（金额区间重叠 / 代理审批链成环 / 角色离职未交接）、阻断清单定位与修复、发布冻结权限快照、带原因调整草稿、刷新持久化、旧实例读旧快照 / 新实例用新版本、带原因恢复历史版本等完整闭环。纯校验函数可单独运行：

```bash
npx tsx tests/domain-check.ts
```

## 审批矩阵与代理链规则

- 每个审批节点必须登记 **审批角色、金额区间（上限为空表示上不封顶）、代理审批角色**。
- 同一审批角色在同一流程内的金额区间不得重叠（边界相接允许，如 0~3000 与 3000~8000）；重叠时报错列出两个节点、角色和重叠区间。
- 代理审批角色构成有向链，成环（含自环）时列出成环节点、角色与完整链路，不得发布。
- 角色目录中已离职角色必须登记交接人；未交接阻断发布，已交接只给警告。
- **发布即冻结权限快照**：矩阵登记与角色目录随版本固化。已发布/已归档流程画布只读，调整只能「新建带原因的草稿」；草稿发布生成新版本。
- 实例在发起时锁定快照版本：运行中的实例继续读取旧快照（画布、矩阵、角色目录），只有新发起的实例使用最新版本。
- 矩阵、草稿、角色交接与实例快照统一持久化到 localStorage，刷新后仍互相对应；流程列表页可一键重置演示数据。

## 分层结构（数据 / 校验 / 界面分离）

- `mock-data/`：种子数据层 —— 流程、版本快照、实例（含快照版本号）、角色目录（含离职/交接边界案例）。
- `src/domain/validation.ts`：纯函数校验层 —— 区间重叠、代理环检测（三色 DFS）、离职交接、结构校验、矩阵提取与实例快照解析，不依赖 React/store，可独立单测。
- `src/store/useAppStore.ts`：状态与数据管理层 —— 发布冻结、调整草稿、恢复、发起实例、角色交接与 localStorage 持久化。
- `src/pages/`、`src/components/`：界面层 —— 编辑器、审批矩阵页、版本历史、表单预览（发起实例）、运行监控（按实例快照渲染）。

## 浏览器验证路径

1. Dashboard 点击「差旅费用审批」进入编辑器，选中审批节点查看矩阵登记（角色 / 区间 / 代理）。
2. 打开「审批矩阵」页查看「跨区域大型采购及多部门联合审批流程」：同时存在区间重叠、代理成环、行政主管离职未交接三类阻断。
3. 在矩阵页登记行政主管的交接人，回编辑器调小区间、改代理角色，校验通过后发布 v1，查看冻结快照。
4. 打开任一已发布流程（如「采购合同审批」）：画布只读，点击「新建调整草稿」必须填写原因；刷新后草稿与原因仍在。
5. 预览页提交表单发起实例；发布调整草稿后再次发起，到运行监控对比两个实例的快照版本（旧实例 v1/v2、新实例最新版）。
6. 版本历史中选择旧版本，填写原因恢复为调整草稿。

## Mock 边界案例

数据集中包含空流程、孤立审批节点、缺少结束节点、未配置条件分支、审批人为空、审批矩阵三类发布阻断（区间重叠 / 代理成环 / 离职未交接）、表单必填校验、超长流程名称、无异常实例，以及由搜索筛选产生的空结果状态。
